Markers · state

All markers live in the consumer project under .cursor/gates/<kind>/<slug>, not in the kit. Parallel tickets use different slugs; another slug does not block this plan. Stop-hooks remind only when the current plan path is known. If the path is unknown — they stay silent so they do not loop another chat. Legacy flat files migrate on read.

Standalone entry points

Lean paths, bug-fix pipeline, create-pr finale, and commands outside the full orchestrator.

·

create-pr (finale of every pipeline)

Skill create-pr: push + always draft, then HITL Pipeline finale (keep_draft / ready / keep_draft_jira / ready_jira). No merge. Requires commit-approved marker from propose-commit. Called after update-docs (+ residual propose-commit) on full /lgt-start-task, after propose-commit on --fast and /lgt-start-issue-task.

·

/lgt-start-task --fast

No tech-spec / plan / critic / review-gate / docs: fetch (if ticket) → jira-transition in_progress → brief → csp-software-developer mode:fast → csp-engineer-reviewer → local-diff-review-gate → propose-commit → create-pr finale. If class=bug — HITL Fast vs issue. The agent never picks --fast.

·

/lgt-start-issue-task

jira-fetch → jira-transition in_progress → fix plan → critic Pass A/B/C → HITL only if blocked → csp-bug-fixer → csp-engineer-reviewer → local-diff-review-gate → propose-commit → create-pr finale. Explicit command always stays on the issue path, even when type=Story.

·

/lgt-write-tech-spec

Tech-spec only, without the rest of the pipeline. If the AC source looks like Jira — the same jira-fetch.

·

/lgt-critique-plan

Ad-hoc critic. Does not replace the approve-plan gate and does not prepare the build clear-marker the way the pipeline path does.

·

/lgt-approve-plan → /lgt-start-build

Full pre-build gate by hand: HITL approve, auto critic, clear → build.

·

/lgt-finish-plan · /lgt-engineer-review · /lgt-update-docs · /lgt-pr-review · /lgt-multi-review · /lgt-capture-escape

/lgt-finish-plan enters the review-gate HITL (code already written). Manual /lgt-engineer-review skips this HITL; /lgt-update-docs remains a separate HITL destination gate. /lgt-pr-review builds a PR Review Canvas by default (diff orientation), then validated Findings; no-canvas skips the canvas. /lgt-capture-escape asks miss (kit via teach-review) or project_secret (local ledger). /lgt-teach-review after a validated miss writes generalized kit instructions on remote learn/… and opens a ready-for-review pull request (not the consumer ledger, except when project_secret is chosen).
